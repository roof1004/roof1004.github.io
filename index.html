인증 · 보안

  • Refresh 토큰 회전 + 재사용 탐지 시 전 세션 폐기, access 토큰은 무상태·HS256 고정으로 alg 다운그레이드 차단
  • 가입·재인증·번호변경용 단기 토큰 5종을 단회 소비 — ConsumedTokenJti insert의 unique 충돌 = 재사용 거부
  • 카카오·구글·네이버·Apple 소셜 검증기를 공통 인터페이스 뒤에 provider별로 구현 (jose 하나로 JWKS 검증과 자체 토큰 겸용)
  • env 스키마를 fail-closed로 수정 — NODE_ENV가 .env에만 있을 때 운영에서 fail-open 되던 문제, Gitleaks pre-commit 훅 운영

개인정보 보호

  • 전화번호는 E.164 정규화 → HMAC(도메인 접두사 분리) + AES-256-GCM으로 저장, 원문은 요청 처리 중 메모리에만 존재
  • SMS 인증: 3분 만료 · 5회 실패 시 30분 잠금(423) · 번호당 10회, IP당 20회/일 — IP도 원문 대신 해시로 카운트
  • 차단된 사용자 프로필은 403이 아닌 404로 은폐해 존재 여부 노출을 막음

동시성 제어

  • 인증과 부화가 겹치면 알 XP·재화가 이중 지급되던 문제 → 활성 알을 PESSIMISTIC_WRITE 락으로 트랜잭션 첫 접근에서 조회하도록 순서 재배치
  • 재화 지갑은 원장(ledger) 기반 + 비관적 락, @Version 낙관적 락은 안전망으로 유지, 락 충돌은 500 대신 409로 매핑

종 판정 알고리즘

  • 인증 기록에서 5개 축 지표를 계산해 종별 점수 산출 → 점수 비례 확률로 종 선택 (설정값으로 순위 가중 모드와 전환)
  • 종마다 시그니처 게이트를 두어, 핵심 지표가 0인데 범용 축 점수로 당선되던 문제 해결 — 의도 일치 10/12 → 11/12
  • DB 없이 도는 12개 패턴 밸런스 리포트 생성기와 회귀 테스트로 규칙 변경을 검증

인증 · 데이터 규칙

  • CHECK/PHOTO/STEP/COUNT/집중 타이머 5가지 인증, 습관별·유저별 일일 XP 2중 상한, 취소는 역거래로 XP·재화 회수
  • 집중 타이머는 클라이언트 보고 시간을 서버 경과시간 + 버퍼로 상한해 과대 신고 차단
  • KST 새벽 5시 기준 service_date를 UTC 저장 DB의 생성 컬럼과 앱 코드에서 동일하게 계산
  • 외부 노출 ID를 UUIDv7 / BINARY(16) public_id로 분리
  • Refresh 토큰 해시 저장·회전, 유예 기간 회원 탈퇴, 차단·신고, 약관 동의 이력 등 출시 필수 기능

🍳 레시비 AI 바이브톤 최우수상

2026.09 · 백엔드 담당

유튜브 레시피 URL을 넣으면 "매장에서 사 먹는 가격 vs 직접 만드는 재료비"를 비교해 주는 서비스 · recibi.kr

가격 3계층

TIER 1KAMIS 실시세 (하루 1회 캐시) · 시드 스냅샷
TIER 2네이버 쇼핑 API / Gemini 검색 그라운딩
TIER 3사용자 직접 입력
  • 2계층은 후보 단가의 중앙값을 쓰고 출처 없는 값은 버림 — 화면에는 "추정치" 배지로 구분
  • 레시피 추출 파이프라인(PoC → 제품 이식, 약 7,000줄) — 설명란에 재료가 있는 영상이 20%뿐인 것을 확인하고 설명란 → 고정 댓글 폴백 사슬로 설계
  • 재료명 정규화 3단계 — 규칙 → DB 별칭 캐시 → 남은 것만 LLM 일괄 호출, 이름당 LLM 1회로 비용 고정
  • 조리 단위(큰술·컵·개·모)를 g/ml로 환산하고, 설명란의 계량 기준("1컵은 180ml 종이컵")을 찾아 기본값보다 우선 적용
  • 팬트리 추천은 LLM이 메뉴만 추론하고 금액은 파이프라인에서만 계산 — 스키마에 가격 필드를 두지 않아 금액 환각 차단
  • Supabase 스키마·RLS 정책·마스터 데이터 마이그레이션, 카카오 로그인·탈퇴, 북마크 API
